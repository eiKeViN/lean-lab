## 同题与公平性

`Moments.lean` 共同定义实际有限加权均值、中心化方差和中心化协方差。
`Contracts.lean` 用同一个 `VarianceClaim` 接受两路线证明，又用同一个 `CovarianceClaim` 接受两路线维护扩展，Lean 已检查四项。

对象是实际 Physlib `DMChannel.on_fin`，输入 `is : Fin n → I` 固定，评分任意。两边外部前提只有输出 `Fintype O`，不要求 `Fintype I`、`Nonempty O` 或额外可测结构。桥的 `Transport` 文件局部安装离散可测结构，并证明测度方差等于共同有限方差。没有修改一般 `expect_val` 或 `Mixable` API，也没有把固定输入偷换为相关随机输入下无条件独立。

原生 `Finite.lean` 使用真实 Physlib 和 mathlib 有限求和/乘积基础：通用乘积求和因子化、单坐标均值、异坐标二阶矩、求和线性及中心平方和均共享。它不调用桥、PMF、测度独立性或 `variance_sum_pi` 来证明结果。`productMean` 是直接加权求和辅助式，最后明确核对真实 `on_fin` 权重，不是替代信道。此为一个强且可复用的基线，不声称它是全局最短实现。

## 实际维护试验：方差 → 双评分协方差

变化是同一固定输入信道上，两组加性评分的协方差等于各坐标协方差之和。两边都没有改方差核心；共同加入中心化协方差定义后，各添加一个文件。

原生路线复用有限和均值线性，加一个共享平方展开极化引理；桥路线增加测度协方差到有限协方差的观察式，调用真实 `ProbabilityTheory.variance_add`，使用既有 `MemLp 2` 证书。然后两边都用同样的三次方差调用、有限和整理和线性消元。**这一维护变化没有显示桥路线明显胜出：新增责任接近，桥少量代数由上游承担，但需要表示和函数表达式适配。** 这比仅替换任意评分参数更真实，但仍只是一个变更样本。

实际故障也保留：

- 原生方差：函数空间 Fintype 的 classical 实例、显式展开 mean、不同枚举实例下将 on_fin 权重用 `Finset.sum_congr` 对齐；未改变数学前提。
- 桥适配：`MeasurableSet.of_discrete` 隐式参数用法；`totalScore` 与函数形式的匹配。
- 桥协方差：上游 `f + g` 与 lambda 的表达式匹配、极化右端加法顺序；一个失败的先改写后归约路径被改为与原生同样的方差三次调用。
- 原生协方差：均值线性和极化首编译成功；中间一次 build 失败来自仍在修的 Finite 依赖，不能算成新消费者证明失败。最终消费者首个实际展开通过。
- 依赖诊断文件最初把文档注释放在 run_cmd 前引起语法错，改为普通注释后通过；它不影响数学证明。

原生是本轮新写、桥基础是上轮成熟资产；失败次数和并行代理耗时不能当作公平开发人时。没有虚构跨版本升级或长期维护数据。

## 设计选择与边界

- 下游保持有限求和、低阶矩和代数操作时，优先强原生 helper；本次它接口更轻、无需测度转换，协方差也没有重复证明整套独立性。
- 已有桥，且下游确实需要测度等式、坐标独立性或继续调用 mathlib 概率分析时，桥提供明确的接口复用价值；本次已验证该接口及固定输入方差复用。未来其他消费者是否摊薄成本，要按实际需求再判断，不能预支收益。
- 没有证明桥接普遍更好、原生普遍更好、升级稳定性或长期维护工时。没有追加更大基准平台或待执行研究队列；本轮有界比较到此结束。
