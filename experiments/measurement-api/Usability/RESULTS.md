## 从下游代码实际看到了什么

**E1：容许自然的专门构造。** 求解者用双射逆像直接定义效果，用 mathlib `Equiv.sum_comp` 证明归一化；概率与对象相等使用新库的 `measure_apply` 和 `ext`。它没有被迫绕经一般粗粒化。这说明原 Physlib 数据载体、mathlib 等价求和和新增观察/外延接口能一起使用；本题没有原库路线对照。

**E2：数学条件由调用者提供，库承担已有构造。** 两条路线都用 Physlib 已有的有序实标量作用和 mathlib 有限和，直接证明 `0 ≤ ∑ wₓEₓ ≤ I`；这部分并不需要新理论。新库路线随后调用 `POVM.binary`，用 `measure_apply` 接 Born 期望。原库路线自行填写 POVM 的正性和归一化字段，并展开 Hermitian 内积或利用二元分布归一化得到概率。原库代码本来就很可用；新库提供的是稳定复用点。新库求解者对结果 1 的效果仍展开 `binary`，这是一个可考虑的对称观察接口缺口，但本轮没有因此继续加定理。

**E3：量子观察与经典估计可以分开复用。** 新库路线用 `coarsegrain`、`measure_coarsegrain`、`pushforward_apply` 完成统计桥接，再单独证明任意两个 `ProbDistribution` 的确定性推前 L1 收缩。最后的量子结论只需调用该经典结果。原库路线自行构造纤维效果，展开内积得到概率和，同样顺利完成；其辅助界针对任意实函数，比新库提交的“两个分布”陈述更一般。原库路线还独立找到较直接的 mathlib `Finset.sum_fiberwise`，后来反过来简化了库内归一化证明。不能用行数或命名声明数断言谁的抽象更好。

**E4：统计视图可用，乘积标签的表示桥接还不够完整。** 求解者能找到 `POVM.ofKraus`，并继续复用 Physlib `CPTPMap.of_kraus_CPTPMap`、`CPTPMap.ext` 和 mathlib `LinearMap.ext`。任意复输入矩阵的总输出相等是先独立证明的，再导出 CPTP 相等，未从统计相等跳到过程相等。主要额外负担集中在遗忘 `j`：下游必须展开筛选、乘积求和和 Hermitian 矩阵投影，最后用 `Finset.sum_eq_single`。这为一般的乘积结果边缘公式提供了具体需求；不是缺少某个本题振幅恒等式。

## 失败、帮助及测量工具的限制

- **环境约定**：E3Base、E4New 的首次编译都因 `module` 的公开声明使用私有导入而失败，自行改成 `public import`。首轮说明的原文在 `321c723`；说明仅在首轮结束后补充，见当前 [LEARNER.md](LEARNER.md)。这两次计为环境错误，不计为测量数学或 API 表达失败。
- **表示和自动化适配**：E4 的其他失败涉及复标量乘法顺序、猜测不存在的 `HermitianMat.mat_ite`、条件/纤维求和，以及 CPTP 到底层矩阵映射的作用边界。原始错误和源快照完整保留。最终分别用 mathlib 标量规则、`apply_ite`、单项和以及显式 `change`/外延解决；不能把这些全部归因于库缺陷，也不能因最后成功而删去成本。
- **审计器误拒绝**：E2New、E3New、E4New 的首次审计 Lean 均退出 0，却因全局 `open Classical` 把 `Classical.choice` 打印成 `choice` 而被旧记录器拒绝。三人自行缩小/移除打开作用域，没有数学变更或父代理提示。父代理用完整公理名重放其首个成功源均通过，说明错误属于测试工具。原拒绝状态仍保留。后续记录器固定 `pp.fullNames`，标准三项白名单未变；[后续工具测试](harness-check-round2.json) 验证真正的 choice 能通过、自定义公理仍被拒绝。

没有学生超时、未完成题、求助后完成或中途库补丁。记录器测试、父代理复核、维护者修库的失败分别记录，没有混入学生次数。维护者简化内部求和时一次 `rw` 匹配失败，随后使用已有恒等式的传递，见 [首轮后失败记录](post-round1-failures.json)。

## 首轮后通用修订及同题迭代

在 `afd4ef8` 存档全部首轮结果之后，新增 [Marginals.lean](../MeasurementAPI/Marginals.lean) 的两条 `@[simp]` 规则：对任意 `POVM (X × Y) a`，第一/第二投影粗粒化的效果分别等于另一坐标上的和。它们不含 Kraus 振幅，不直接提供 E4 的结论；对联合读数、保留一个经典寄存器等客户也适用。后一用途是设计推演，本轮实测客户只有 E4。另复用原库路线找到的 `Finset.sum_fiberwise` 简化内部归一化；未改变已有数据或公开类型。

[首轮后变更](POST_ROUND1.md) 和 [公开类型兼容记录](public-type-compatibility.json) 区分了新增与原接口。修订后 30 个 API 声明、20 个原命名契约及两个完整 Physlib 假设检验版本重新通过检查，详见 [当前库验收](../evidence/acceptance.json)。首轮全部 44 个声明的首个成功源和最终源在新版库上回归也通过，见 [新版回归复核](regression-review.json)；这不是首轮证据的替换。

随后给**原 E4 求解者**发送同一题和新库的普通入口，允许复用自己的旧解答，未告知新定理名或预期简化位置。[分配全文](round2-assignment.json)、[新库/原题哈希](freeze-round2.json)、[后续证明](Submissions/E4Revisit.lean)、[事实记录](Submissions/E4Revisit.md) 和 [两次调用的完整记录](records/round2/E4Revisit.json) 均保存。

它自行查阅新库并使用 `POVM.coarsegrain_fst_mats`。`coarsegrain_finePOVM` 从本地展开筛选/乘积/单项和，变为 POVM 外延、边缘公式、Hermitian 投影及原有局部效果求和结论。一般 Kraus 振幅与总输出计算仍由客户提供。它还删除未用的实例，令若干辅助代数结论假设更弱。一次普通编译、一次审计均成功；父代理独立检查该版本全部 12 个声明及首个成功源，见 [后续复核](round2-parent-review.json)，仍仅标准公理。

这是**受反馈影响的同题迭代**：库适配过该场景，求解者保留了经历和代码。能确认的是通用接口承担了原下游表示转换工作，以及全部结论维持成立；不能把尝试数或耗时变化归因于库，也不能计为第七个独立首轮样本。

## 可复现性与适用边界

[复现说明](REPRODUCE.md) 区分冻结首轮、当前库回归和同题迭代。`records/*.json` 内嵌每次调用的原始源、完整编译输出、退出码、选项、时间、问题/库版本和哈希；不依赖本机忽略的 `results/`。当前 `recheck.py` 可从这些公开档案重放首个成功源和最终源，默认仅写 `results/`。哈希校验只确认档案完整，实际 Lean 重放另行标明。

六人使用 `fork_turns=none`，不继承设计对话；相同继承模型和 `max` 推理设置，工具未提供可据以独立核实的精确供应商模型 ID。分配提示没有指定引理、Lean 陈述或解法。原路线明确禁止读取扩展库；显式导入由记录器限制。隔离依靠新上下文与提示约定，共享文件系统**没有 OS 级访问隔离**；资源浏览情况依据事实记录，不能据此声称技术上排除了所有潜在泄漏。数学解法没有跨代理转发。

每题任务预算 25 分钟、每个 Lean 进程 120 秒、单线程；所有记录过程均未超时。精确任务派发墙钟未仪器化，进程耗时也受并发和缓存影响，不报告端到端速度收益。每条对照路线仅一名代理，数学探索选择有差异，不是统计研究或人类用户研究。原库路线能使用 mathlib、Physlib 和原有桥；两名原库求解者最终未使用桥。

本轮合理的设计结论是继续扩展已有 `POVM`/`CPTPMap` 载体的构造、观察、外延和一般表示转换接口：它们已被下游自行发现并组合，也不妨碍更专门的数学构造。尚无证据支持新增一个通用 instrument 结构，或把统计与过程语义合并。顺序条件测量、反馈、归一化后选择态、连续结果和 Lean-QIT instrument 迁移未在这组练习中检验；依赖使用锁定官方缓存，未重新内核检查全部依赖。
