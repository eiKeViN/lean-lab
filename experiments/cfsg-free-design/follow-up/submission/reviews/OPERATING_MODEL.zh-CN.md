# CFSG 智能体协作实施系统：组织、协议与产能设计

版本：2026-11-11。作者角色：agent-systems-architect。本文件是未来实施设计，不是已运行系统、经验证的 Lean blueprint 或 Axiom 内部流程说明。

本设计已读本轮 `USER_FOLLOWUP.md`、上一轮 `previous/PLAN.zh-CN.md` 和 `sources/README.md`。接受完整 CFSG Lean 形式化已经存在、任务可行这一前提。公开发布所述“数学家和工程师协调数十智能体、约24天”只说明一个公开完成事件，不足以反推内部组织、可用基线、资源、搜索效率、失败次数或本项目工期。本文件中的人数、并发槽、硬件、时限、价格、吞吐和阶段周期，全部是**建议配置、实验阈值或情境假设**，均非 Axiom 内部事实。

与旧稿不同，本轮采用**审计后复用优先，缺口自主重建**：未来请求取得公开 CFSG 完整源码、blueprint、工具链与允许使用的构建工件；允许复用任意粒度中间引理和重型模块，但须核查完整源码依赖、公理、数学前提、许可证、目标语义及重放成本。最终分类声明本身不能成为本项目分支证明的前提，也不能以一个整体导入掩盖固定 TauCeti 载体的识别与全名单正确性。没有取得的材料目前仅登记为资源请求，绝不登记为已读或已验证。

## 1. 成功标准决定系统结构

智能体系统最终应产出四项相互连接的结果：固定 `TauCeti.ClassificationStatement` 的无条件证明；每个固定 `CFSGIndex` 载体的有限性和单性；所有分类出口到固定载体的实际乘法同构及必要参数正规化；可从锁定源码、证书和工具链独立重建的完整依赖闭包。名字、群阶、局部结构相同不能代替同构。

实施主体是智能体：智能体阅读和对照文献，建设依赖图，编写 Lean，生成和检查计算证书，搜索证明，互相审阅，维护兼容层，编排集成与发布。人类负责提供设施、授权预算、帮助取得文献和源码、处理超出智能体能力的数学裁决及独立验收。人类不必逐个手写证明，也不逐个批准普通调度动作。

三个边界固定不变：数学目标和具体列表不可被代理静默修改；证据等级不可因多数代理同意而提升；最终数学可信性由 Lean 可重放证明和公理政策保证，目标是否表达正确数学由来源及语义审阅保证。现在四个会话只是本轮规划编制条件，不约束未来实施。

## 2. 未来组织：64槽先导，256槽常态，按收益弹性扩容

“槽”是可同时执行任务的智能体进程容量，不等于雇员、固定模型账号、GPU、持续满负荷活动或独立数学专家。一个长期角色可轮换模型实例；每次实例必须按交接协议接续。模型厂商、规格、上下文长度和具体调用方式由试验选择，不假定某个未公开模型具有特定能力。

先导配置是6个八席编队加16个共享槽，共64槽。六队先覆盖归纳基础、复用映射、Lie出口、散在出口、局部/奇数阶深样本、重型桥接/总装。第一个月以小任务测量并发8、16、32、64；稳定后到128、256。只有可证明存在足够已就绪任务、瓶颈非人工审阅/构建、且扩容确有收益时才试512；512不作为成熟期默认开销。

### 2.2 决策权限和隔离

| 动作 | 执行者 | 必要约束 |
| --- | --- | --- |
| 搜索文献、建候选分支、运行锁定编译、创建子卡 | 编队智能体自主 | 任务预算、允许依赖、来源权限；禁止把候选记作证明 |
| 改局部证明、补引理、选择等价证明路线 | 卡负责人和集成员 | 保持已批准接口；审阅和影响构建通过 |
| 增加卡的假设、删去例外、改变模型出口 | 不得由作者单方决定 | 发接口变更请求；消费者和独立语义审阅员共同确认 |
| 合并普通实现 | 自动合并机器人 | 独立代理审阅、锁定CI、声明/公理报告、消费者集成通过 |
| 合并核心定义或跨域接口 | 接口评议组 | 两个不同方向代理和指定人类领域专家处理高影响语义变更 |
| 调整编队和已授权预算内的槽位 | 全局调度员 | 公开事件日志、成本/关键路径约束、无擅自改变目标 |
| 提升总预算或申请新设施 | 系统提出具体资源单，人类出资负责人决定 | 给出报价/情境、可审阅用途、退出条件 |
| 放宽公理、改变最终命题、替换固定载体 | 普通代理无权 | 单独目标变更程序；不得以现行项目完成名义发布 |
| 发布“完整CFSG” | 独立审计组和人类验收负责人 | 根定理、名单正确性、闭包审计、两处冷重建均满足 |

仓库写权限按领域路径和分支授予，公共定义目录由接口队管理；发布机器人独占主干写入凭据。上游源码只读，代理可写自己的隔离工作树和任务工件，可读取已授权文献；部署、预算和对外通讯另行授权。该隔离用于防止误合并、提示注入或环境污染，不把模型口头承诺当作系统边界。

## 3. 工作包、定理卡与消息协议

### 3.1 三层账本

第一层“工作包”对应数学目标，例如“非C2残余分支”“Monster固定呈示桥”。它有最终出口、所有参数/例外、领域负责人、资源上限和替代路线；不能因它很大就成为一个永久黑盒。

第二层“定理卡”是分派和验收的基本单位。推荐可在一个到三个代理工作日内形成可审阅结果；预计更大就拆分。这个长度是调度目标，不能靠把困难证明改成未证假设达成。K00按“族×性质×参数区间”拆分按需消费，局部队不等待全部26个散在群的Out/乘子表；A00–A02按实际通用引理和各族切片释放，A₁不等待全E₈；N00按每个小同构随对应模型完成。第三层“尝试”是某个代理在指定环境、预算和策略下的一次搜索。卡可有多个竞争尝试，只有首次被消费者集成验收的结果计为产出。

未来机器账本建议使用如下字段。示例是协议设计，不是已经存在或通过 elaboration 的 Lean 声明：

```yaml
card_id: L-BRIDGE-FIXED-0007
schema: theorem-card/1
package: A00
revision: 3
status: ready
owner_pod: lie-bridge-1
contract:
  proposition_file: Contracts/Lie/FixedPointBridge.lean
  proposition_sha256: <规范化后命题与完整环境的摘要>
  binders: <完整类型、宇宙、群实例和局部假设清单>
  output: <固定点同构；不是只输出同阶>
  parameter_ranges: <所有参数与例外>
  allowed_induction: []
inputs:
  base_commit: <固定提交>
  toolchain_lock: <锁文件摘要>
  allowed_imports: [<已验收依赖>]
  required_cards: [<带revision的前置卡>]
  source_locators: [<版本、页码、定理号、勘误状态>]
acceptance:
  consumers: [<一个真实消费者测试文件>]
  required_reports: [build, axioms, declarations, provenance, replay_resources]
budget:
  max_agent_hours: 24
  max_tokens: <由该类卡试验确定>
  max_parallel_attempts: 3
handoff:
  last_good_commit: <提交>
  failures_index: <负面结果对象>
  next_discriminating_action: <能改变路线选择的下一步>
```

实际实现须另外保存完整命题源码和 Lean 环境摘要；不能只依赖易变化的 pretty-print 文本或不透明 hash。显式登记许可证、引用祖先、证书格式、核验器版本、预期性能和可用数据权限。模型版本、提示模板和工具调用日志保留作复现调度的证据，但不算数学证明。

### 3.2 状态机和验收

状态流程为 `proposed → specified → ready → leased → candidate → kernel_passed → independently_reviewed → consumer_integrated → released`。支路状态有 `blocked`、`superseded`、`failed_attempt` 和 `quarantined`。前四个状态不能表示定理已经成立。`kernel_passed` 表示候选在指定环境通过，尚未保证命题是要求的命题。

`specified` 要求完整假设、输出和来源；`ready` 要求允许依赖已经可用、消费者规格确定、预算和领域责任明确。尚缺前置证明的卡可做文献与接口工作，不能冒充已就绪实现卡。`candidate` 应交付最小补丁、证明说明、实际声明类型和资源报告。`consumer_integrated` 要在真实上游目标里使用该结果，确认假设可提供、类型可运输、参数可合法构造。

卡被拆分后，父卡仍保持未完成，直到全部必要子义务和总装通过。不能把“已关闭100个容易子卡”换算成一个重型父包完成。卡若因新增前提而变更命题摘要，原尝试和通过日志保留但不沿用验收状态。

租约记录 `card_id + revision + attempt_id + holder + expiry + environment`。建议租约30分钟、每5分钟心跳，进程崩溃后自动回收；超时和重试是编排策略，不是判定数学失败。用比较并交换写入认领状态，每次续租/转派带单调递增的租约世代号；只有当前世代可更新权威状态，过期实例迟交结果只能另登记候选，不能覆盖接手者。事件按唯一ID幂等处理，避免网络重试重复验收。明确批准的三路竞争尝试各有独立尝试号。

### 3.3 事件和交接协议

代理不依赖自由聊天传递关键状态。消息最少包含事件类型、卡和版本、发送角色、输入提交、输出工件、阻塞原因、消费者及所需动作。事件类型包括 `CLAIM`、`SUBGOAL`、`PATCH`、`FAILURE`、`DEPENDENCY_REQUEST`、`INTERFACE_CHANGE`、`REVIEW`、`INTEGRATE`、`HANDOFF`。聊天可解释事件，账本才是状态来源。

任何会话终止、上下文轮换、模型更换和跨队转派，必须生成交接包：精确目标；基线及最后可编译提交；有效patch；已证子引理；失败尝试及可复现错误；尚未证明的数学步骤；允许依赖和禁止路线；下一项区分性实验；已花预算。接手代理先重放最小目标再继续。不能把一段“我认为基本完成”的自然语言当作交付。

## 4. 调度：同时经营证明依赖和研究选择

全局维护两个相互关联的图。证明图只有真实声明、条件及已确认依赖，是发布依据；研究图允许候选路线、未证猜想、替代模型和成本分布，用于探索。不得把研究图的一条“预计可用”边悄悄变成发布图的已证依赖。

### 4.1 就绪队列和优先级

就绪队列按以下量排序，公式仅是初始调度启发式，试验后调参：

`priority = (3×关键路径贡献 + 2×解锁消费者数 + 2×路线不确定性降低 + 复用价值) / 预计代理时`。

各量先按0–5标度评分，预计代理时给区间而非伪精确点值。卡的证明风险、人工等待和峰值内存另作约束，不混入一个不可解释分数。优先处理能打开多个分支的共享接口、能暴露主路线错误的深样本以及到固定载体的真实出口。已就绪队列不足时，调度员分配拆卡、复用审计和文献核对工作；不让实施员重复消耗同一个未开放依赖。

初始槽位预算建议为：65%主路径实现与集成，15%竞争/替代路线，10%工具和共享API，10%独立审计和复现。该比例是运行时分配，不与前述角色表重复计人数；固定审计职责不得因主线赶工消失。高风险桥接允许在一周内临时将替代路线提升到30%，从主路径未就绪任务回收槽位。

同一定理默认最多三种明确不同的策略并行：例如复用并适配现成证明、经典文献直接证明、重新选择中间表示。纯换措辞调用同一模型三次不算三条策略。候选成功后取消尚无独立审计价值的重复搜索，保留日志。仅在语义风险、检查成本或关键路径收益足够时保留第二实现。

### 4.2 依赖预约和防止空转

未来两周滚动规划“消费者需求单”：所需准确命题、最晚可用时间和可接受替代接口。生产者给出预计窗口；消费者在等待时做其余子分支或编写使用测试。共享库任务采用服务级目标，例如就绪接口请求一个工作日内分诊、三个工作日内给可执行处置；这些是管理目标而非数学完成保证。

每个编队在制实现卡不超过实施员槽数的两倍；全局每日检查长等待卡、没有消费者的卡、重复声明和预期解锁未实现的卡。每日自动生成关键路径和人工问题队列，周度复核资源重排。只给关键路径开更多实例，不能消除必须顺序证明的依赖；调度系统明确显示这部分下界。

## 5. 证明搜索与编译流水线

每个实施尝试按“检索—规格核对—最小目标—策略树—局部编译—消费者集成”执行。

1. **检索已有内容。** 同时检索固定本地库、经审计的公开实现、声明类型索引和来源映射。检索结果显示实际环境中的完整类型、公理闭包和导入成本；只找到文件名不算可用定理。优先尝试数学等价的已有证明加显式运输。
2. **形成最小目标。** 复制完整局部上下文和允许imports到隔离工作树，验证问题确实存在。区分载体/实例失配、缺引理和数学路线缺口，避免把一条 coercion 错误当成未建理论。
3. **搜索策略树。** 每个节点保存目标、策略、引理来源、环境摘要、结果及耗时。精确检索失败后才扩大到构造子/同构运输/归纳/文献重建。外部GAP/Magma或数值实验只生成猜想和证书；不能将其输出当结论。
4. **局部重放。** 快速检查修改声明及实际受影响文件；失败返回原始Lean诊断与最小重现，不仅把整个日志交给下一个模型。达到卡预算后按失败分类转轨。
5. **总装重放。** 独立构建服务对补丁执行影响闭包构建和消费者用例，生成声明类型、导入与公理报告。作者环境中的缓存成功不等于集成通过。

编译采用三层队列：秒至分钟级编辑反馈、卡/消费者级集成、包级及发布级冷重放。按改动触发相应层级；没有改动或新风险不重复跑全仓。构建结果缓存键必须包含Lean工具链、所有依赖提交、源码、编译选项、证书和所用检查器；不同环境的 `.olean` 不能混用。内容寻址缓存加速开发，发布另做干净源码构建。

编译服务记录排队、elaboration、kernel、内存和IO时间，避免将“模型闲等编译”误算为推理产能。单卡heartbeat/内存额度按类别配置；异常证明项交给性能代理作引理分块、证明结构调整或证书压缩。不得以扩大可信计算基础换取无说明的提速。

规格区与发布区物理隔离。规格可定义命题、结构和显式条件接口，候选证明可在不可导入发布的沙箱中有洞；发布依赖闭包不得包含未完成证明、额外数学公理或隐藏分类假设。对于复用模块，完整追踪其传递依赖，不因某个重型声明本身已经编译就省略闭包审计。

发布门禁对根分类声明和全名单有限单性声明逐个导出实际类型及传递公理闭包，包含所有隐含绑定、typeclass参数与宇宙；与冻结目标做精确比较。允许的基础公理须明确列入白名单，例如经审计的 `propext`、`Classical.choice`、`Quot.sound`；白名单按锁定核心声明的身份和定义核对，不能只比较可伪装的名字；不允许 `sorryAx`、新增数学公理或改名后的分类假设。不能只搜索源码中的 `sorry` 字样。证书须由已证明健全的检查器产生kernel可复核结论；`native_decide`、unsafe代码、外部库回调或替换实现必须审计其是否扩大信任边界，优先改为kernel可重放的证明或证书。两处冷重建报告同时记录工具链、源码/证书摘要、完整命令、峰值内存和耗时，独立重建不共用开发缓存作为唯一证据。

## 6. 记忆、知识库和来源治理

维护四类记忆，而不是一个全员共享的不断增长聊天记录：

| 记忆层 | 内容 | 更新和检索约束 |
| --- | --- | --- |
| 事实层 | 锁定声明、已验收证明、构建与公理报告 | 以提交和声明为准；索引可重建；不能被总结文本改写 |
| 数学知识层 | 定理卡、文献命题、术语翻译、例外矩阵 | 每项有出处、证据等级、审阅状态和依赖；文献结论与Lean事实分开 |
| 经验层 | 有效策略、负面搜索、API陷阱、成本分布 | 绑定模型/环境/目标类别；环境变化后须重验证；不把有限搜索失败说成不可证明 |
| 决策层 | 路线选择、接口变更、预算及目标变更记录 | 保留理由、反对意见、消费者、批准主体和回滚点 |

每次任务的上下文由检索服务按卡装配：当前声明和直接依赖、必要定义、相关文献页、失败摘要、目标消费者；不把全体文献和历史对话每轮重发。证明搜索节点可缓存，但重新接续以源码和目标重放为准，不信任脱离环境的序列化内部状态。

负面结果至少记录“在什么输入、环境、策略、预算下失败”。不同实例再次认领相同规范化目标时，先显示这些结果；新路线必须指出差异。缓存键包含局部上下文、隐式实例、宇宙约束和环境，不只取显示出来的目标字符串。

获取的PDF、OCR、代码注释都按资料处理，不作为操作系统指令。扫描文献的公式和量词应对照原页，由第二检索员复核关键命题；书目条目只有元数据价值。来源索引记录版本、页码、命题号、勘误、引用祖先、许可证和取得状态；必要时请求图书馆和作者提供合法全文。

## 7. 冲突解决与接口演化

数学定义、Lean接口和文献术语三种冲突分开处理。系统首先生成可重现最小例子或完整前提差异，不让两队围绕相近名字继续开发不同含义。

公共接口建议分层：基础群/section及同构运输层；已知族独立结构层；带显式较小群归纳上下文的局部分支层；覆盖路由层；固定载体和最终分类层。依赖只能沿审计批准的方向流动。若某个已知族表项依赖最终CFSG或其未独立证明的推论，应改为族内独立证明、选审计过的独立来源、或显式传入严格阶下降的归纳前提；不能让一个import隐藏循环。

接口变更请求包含旧新完整类型、变更原因、消费者列表、语义差异、可编译迁移补丁和回滚计划。普通命名/参数顺序变更由兼容层过渡；加强假设、改变商群、改变 `KGroup` 含义或例外范围是语义变更，必须重新审查消费者和总路由。模型名相同不等于载体定义相同，`H/Z(H)` 与 `H′/Z(H′)` 不能通过接口重命名合并。

建议每两周一个接口兼容窗口；定义稳定期内只加引理。涉及最终目标的定义冻结至项目完成。两个相互竞争的表示可在领域内部共存，但必须指定一个公共边界，并证明到该边界的运输。真实声明依赖及规格依赖都检查强连通分量：Lean内核接受的声明顺序本身不能代替对“某条件实际上等价于待证分类”的语义循环审阅。

合并冲突由集成代理在受控分支解决，重放受影响消费者；不让原作者直接覆盖另一实现。数学争议若一日内不能通过反例、具体定理或编译消解，则写成精确问题交领域专家；人类裁决回写决策层，附来源和所需证明，不以会议结论代替Lean证明。

发现已验收卡存在错误规格、来源不独立或未获批准的可信依赖时，审计服务撤销该卡的验收凭据，沿消费者反向依赖闭包标记隔离，取消相关发布资格，保留最后一个有效版本作回滚点。其他未受影响分支继续。修正后重新审阅和重放，不以旧版绿色CI或累计产能维持完成状态。

## 8. 失败检测、转轨与升级

以下时限是初始管理阈值，可由先导数据修订；触发的是重新诊断或资源变化，绝不触发降低证明标准。

| 观察 | 自动诊断和转轨 | 保留的义务 |
| --- | --- | --- |
| 同一Lean错误修补3轮仍重复，或30分钟无新有效信息 | 产生最小重现；转接口/实例专家；改用显式同构或不同表示 | 原命题、原环境和所有实际假设 |
| 单卡用完预算或三种策略均未闭合 | 停止同质重复；拆缺引理、搜索可复用实现、转人工数学问答 | 卡继续未完成，失败历史公开 |
| 阅读后发现文献多出K假设、有限生成或特殊参数 | 重新指定接口和归纳上下文；加入被遗漏分支或换来源 | 未覆盖分支不能从覆盖矩阵删除 |
| 公开模块依赖最终分类、Schreier或未经允许公理 | 隔离传递闭包；只提取独立子模块或自主重建 | 被拒复用部分仍列为真实缺口 |
| 有限呈示只能给到模型的满射 | 搜索规范形、阶上界、中心核或逆映射证明；必要时换模型 | 不宣布呈示有限或与模型同构 |
| 小群枚举超内存，Monster路线依赖巨型置换枚举 | 终止该算法；转局部几何、中心扩张、结构证明或分块可检证书 | 巨型群独立路线和预算不可被小样本替代 |
| 证明项检查超出发布窗口 | 分块引理/证书、优化已证检查器、建立峰值资源计划 | 不把外部无证书计算加入数学公理 |
| 共享API改动使大量消费者失效 | 回滚合并、冻结接口、兼容层迁移，重排生产者 | 不通过暂时增加未证假设恢复绿色CI |
| 来源无法取得或许可证不允许所需复用 | 请求图书馆/作者/法务；换合法来源或自主重做 | 不凭摘要猜内容，不传播未授权全文 |
| 同一重型路线一周内无不确定性降低 | 发路线比较单；两队做差异研究；专家会诊后继续/切换 | 已证基础保留，父目标和出口保持 |

T07残余分支具体拆为spec/local/reduce/cases/exit/cover；spec先行不算证明完成，也不能预设其例外只有有限多个孤立群，真实来源产生参数族时逐族记录。D01契约同样先行，数学桥接未闭合就保持未完成。

人类升级单必须是可答问题：“定理X的假设H是否能由当前归纳上下文推出？反例搜索到何范围？已试A/B；请确认文献Y第Z页是否还有例外。”不能把几百页未经拆分的工作丢给专家。专家回答通常产生一张新卡或一条来源映射，仍由代理实现和核验。

如某个固定载体被证实与要求不同，系统提交精确差异、反例/证明及可选修复，暂停该出口的完成声明，同时继续无关分支。可行性前提不允许推导“任何指定定义都必然正确”；该情况由项目目标治理处理，不能静默换定义。

## 9. 需要人类提供的设施和专业支持

### 9.1 软件和资料

立项时请求人类提供：完整固定Mathlib/TauCeti源码与真实Lean工具链；公开CFSG完成项目的完整可用版本和允许取得的blueprint/构建说明；Git仓库、隔离工作树和分支保护；对象存储与可恢复事件数据库；Lean语言服务器、声明/依赖/公理导出工具；检索索引；证书格式和已证检查器建设能力；可授权使用的模型API或自托管推理端点。

文献设施包括大学/研究所图书馆合作、电子全文与勘误获取、旧论文扫描/OCR和人工公式复核、ATLAS及相关数据的许可与来源管理。可使用GAP/Magma、Sage、有限群数据库及计算代数专家帮助生成候选和证书，但其未经认证结果不进入最终证明链。软件许可证和资料用途由人类负责落实，代理记录每个复用工件的来源。

### 9.2 计算与运维配置假设

先导64槽可从8台构建节点开始，每台32核/128GB内存，另提供适配代理沙箱和索引的通用计算、20TB对象存储及一台物理分离的冷重放机。该配置仅是采购起点，不能保证某个重型证书适用。

256槽常态配置建议：

- 代理工具沙箱总容量约512 vCPU、2TB内存，按每槽2 vCPU/8GB的上限预留，空闲可回收；模型推理可以由外部服务承担，沙箱CPU不等于模型算力。
- 构建/证明检查池另设32台64核/256GiB节点，初始合计2048核、8TiB内存；其中4台若替换为1TiB大内存节点，总内存变为11TiB，设施报价随替换更新，节点总数仍为32，不能重复计费。
- 证书/计算代数专用队列4台64核、512GB–1TB节点，按任务启停；两处独立冷重放节点与开发缓存隔离。
- 共享NVMe缓存及初始100TB可扩展对象存储；关键源码、证书和日志做版本化备份、定期恢复演练和校验。
- 模型端点按聚合token吞吐、并发和尾延迟签配额；仅有“256会话”而没有足够token配额并不能实现256活跃槽。

不预设需要自建巨型GPU训练集群。模型推理自托管是否划算，要以实际模型许可证、质量、token吞吐、功率和运维成本实验比较。若专用证明模型/检索模型确有改善，可独立申请微调或推理集群，须与模型API费用互斥核算，避免双计。所有硬件均为未来可请求建设的设施，当前房间没有Lean或网络不是未来限制。

### 9.3 人类配置假设

建议常态20名全职等效人员：8名有限群/局部分析/角色论/几何/Lie/散在领域数学专家，4名Lean与证明工程专家，3名基础设施/工具工程师，2名文献与数据专员，2名独立审计人员，1名项目资源负责人。专家可按机构合作分时组成，不必全员同地雇佣；高风险方向另设可按问题付费的外部顾问名单。

人类数学专家的重点是顶层命题语义、关键桥接与例外、独立性/循环判断和智能体未解问题。所有普通卡由代理交叉审计和kernel检查；不要求20人逐张批准海量基础卡。高影响定义、每个重型包的主接口、路线切换及根定理必须有人类领域审阅。人类审阅队列的到达率、服务率和等待时间纳入吞吐报表，必要时扩充专业合作而非盲增代理。

先导可采用8–12 FTE及兼职专家值班；20 FTE属于扩容情境，并非历史事实。数学负责人与独立审计员对同一重型结论不能是唯一作者和唯一验收人。

## 10. 首90天试验：先测深度，再测并发

90天是建议先导窗口，不是已知CFSG重建工期。若大量可靠模块可复用，深样本可能迅速推进；若目标载体桥或来源独立性仍有缺口，就让试验暴露这些缺口而不是预设全部重写。

| 时段 | 主体和任务 | 必须交付的证据 |
| --- | --- | --- |
| 第1–7天 | 基础设施代理、复用队与人类资源人员获取工具链和完整材料；选择复用基线 | 两台机器锁定重建；目标定义摘要；公开实现的取得/许可证/审计边界表；未取得材料清单 |
| 第8–21天 | 64槽试运行；声明检索、定理卡服务、租约、事件和CI跑通 | 循环群出口及一个具体载体消费者；至少一个完整复用模块到TauCeti接口的适配；失败和成本日志 |
| 第22–45天 | 六队选取深样本：section阶归纳、固定点桥、M11呈示、奇数阶接口、分量/K表、QTKE/几何接口 | 每样本明确来源、传递依赖、未证假设及消费者；至少两个重型模块的闭包审计与适配试验；Monster单独来源/路线评估及至少一个关键片段的可重放审计试验 |
| 第46–60天 | 用独立任务池做16/32/64槽及候选128槽试验；隔离比较复用/重建路线 | 吞吐、成本、合并返工、人工等待、编译瓶颈及语义缺陷报告；不能拿同一题第二次热启动冒充并发增益 |
| 第61–90天 | 通过门槛则扩至128/256；统一全任务图和高风险路线 | 每个顶层分支、17个Lie构造子和26个散在群有负责人、复用途径或缺口；剩余关键路径与区间预算；更新下一阶段里程碑 |

试验不是要求90天独立完成M11、所有重型桥或Monster。未完成样本也须产生可复现、能改变资源决策的信息：实际缺失定理、错误前提、依赖深度、验证成本和可行备选。简单运输引理高通过率不能替代奇数阶、quasithin或Monster的深样本。

### 10.1 计量单位和对照设计

主要产能指标是**净消费者集成卡数**：首次通过指定真实消费者、独立审阅和kernel检查的卡记1；重复证明不重复计数；被撤销或因错误规格失效的卡扣回。按基础/API、模型运输、文献重建、重型桥接、证书分别报告，不能只报总卡数。

卡粒度会影响数量，故同时冻结抽样任务的命题摘要、父目标和验收难度分层，报告每个父包剩余义务及关键路径。不得通过把 `rfl` 拆成100张卡制造产能。配套指标有代理时/集成卡、美元/集成卡、消费者首次成功率、7/30日返工率、人工审阅时/卡、来源核对率、CI尾延迟、峰值核验资源及路由未闭合数。

建议抽取60–100张预审卡做先导，其中至少三分之一为跨模型/跨领域或重型接口卡。并发实验使用不同但分层匹配的任务池，固定模型/工具版本并保留失败；一次任务不得因重试和多个模型被记成多个成功。样本按领域/包聚类给出区间，显式报告少数深样本的巨大不确定性，不将多个相似小引理当独立观测。

建议扩容门槛：消费者成功率≥80%，7日返工率≤10%，全部被采纳结果符合公理政策；人工与编译等待均未成为主要瓶颈；从N到2N槽的净吞吐至少增加1.5倍且单位集成成本增幅≤25%。这些数值是待试验的管理阈值，不是数学真实性指标。语义缺陷导致最终目标失真，即使数字达标也不能扩容发布。

## 11. 全任务里程碑：以闭合义务而非日期承诺

| 门槛 | 可验收产物 | 智能体系统的下一动作 |
| --- | --- | --- |
| M0 环境与证据闭合 | 固定工具链、目标语义、源码来源和访问边界；重建通过 | 开放复用映射和领域样本，不先要求从零建所有基础 |
| M1 复用/缺口图闭合 | 顶层工作包均映射到可审计模块或明确缺口；每条分支和例外有责任队 | 对复用模块做声明级审计，对缺口拆卡；建立剩余关键路径 |
| M2 垂直出口闭合 | 循环/交错/至少一个Lie与一个散在出口有具体载体同构链；归纳接口可用 | 用同一协议扩到所有出口，重排重复劳动 |
| M3 重型平台闭合 | 奇数阶、signalizer、分量、特征2及quasithin所需的每个实际依赖有证明闭包 | 把研究图已证节点转入发布证明图；关闭路由残余 |
| M4 全路线及名单闭合 | 各分类分支、K假设消去、17+26族有限单性和呈示/模型桥全部集成 | 生成根定理、全宇宙出口、传递公理与语义审计报告 |
| M5 独立发布 | 两处从锁定源码和证书冷重建，所有根声明、列表正确性及资源门槛通过 | 归档发布，保留维护编队和升级回归样本 |

M0–M5可有大量并行，M3不会因为系统导入了一个名字很大的定理而自动通过。复用优先可能极大缩短M1–M4，具体收益由完整源码取得后的审计决定。用6、12、24个月作现金流和资源占用情境可以帮助立项，但目前没有证据给它们分配概率；既不继承旧稿15–25年工期，也不继承24天完成的承诺。

## 12. 可复算的产能、工期和成本模型

### 12.1 产能与关键路径

令 `S(t)` 为并发槽数，`u(t)` 为实际利用率；`b_k` 为某类卡平均尝试代理时，`a_k` 为产出一个进入消费者/独立审阅的候选所需平均尝试数（含失败），`q_k` 为消费者/独立审计保留率，`v_k` 为集成后返工折减。简化类内吞吐为：

`λ_k ≈ 分配给k的活跃代理时 × q_k × (1-v_k) / (b_k × a_k)`。

真实产能还受就绪卡、构建检查、人类审阅和集成服务率限制，因此整体以这些瓶颈最小值为上界。公式用于解释测量，不假装所有类的卡可互换。估工期时至少保留：剩余工作量/实测产能、顺序依赖关键路径、人类稀缺服务时间、发布重放四个下界。用剩余DAG和各类实测耗时分布做情境模拟，按月更新。

一个仅供计算说明的假设：有256槽、利用率0.65、每天可计24小时、平均每个进入审阅的候选耗8次尝试×6代理时，则未扣审阅和返工时约 `256×0.65×24/48 ≈ 83.2候选/日`。这个数字不是预测；若重型桥需50次×24代理时，同样资源约3.3候选/日，而且可能没有足够并行度。若检索/审计等共享槽另有占用，还须从可用代理时扣除。正因差异巨大，禁止用单个小群试验推算全部CFSG。

### 12.2 Token与设施费用

对模型m，按实际账单计：

`C_model = Σ_m [(T_in,m × p_in,m + T_out,m × p_out,m)/10^6 + 其他服务费_m]`。

缓存命中、长上下文、批处理和重试按真实计费项记录；输出/隐藏推理若由供应商收费，须进入相应token项。不要把模型可见文本长度当全部计费量。也不要同时按槽日和token对同一服务重复计费。

下面是假设价格，不是任何厂商现价：输入每百万token 5美元、输出每百万token 25美元；每活跃槽日输入600万、输出80万，则50美元/活跃槽日。稳态256槽、利用率0.65、每月30日的模型费约 **249,600美元/月**；若满负荷，约384,000美元/月。利用率是相对该“活跃槽日token量”的占用，不在token实账上再次折扣。

作规划敏感性分析，可把总模型费乘0.25、1、4，覆盖价格、上下文重复和搜索量变化；高价情境不自动意味着更高产能。64槽同口径稳态模型费约62,400美元/月。工具/构建池、存储、证书CPU、网络及冷重放可先按50,000–150,000美元/月预留，再以云报价或折旧/电力/运维细项替换；自建GPU推理另做互斥方案比较。

### 12.3 人力、期间与现金需求

假设20 FTE、每FTE年全负担成本250,000–400,000美元，则人类专业/运维服务为5–8百万美元/年。此项包括规划的人类团队，不应再把同一人的评审费用重复计入外包；额外顾问、文献许可和特殊工程另列。

以256槽稳态、利用率0.65、上述模型价格、设施50,000–150,000美元/月、人类20 FTE为示例：

| 费用项 | 每月基准区间（美元） |
| --- | --- |
| 模型服务 | 249,600 |
| 构建/沙箱/存储/专用核验设施 | 50,000–150,000 |
| 人类专业服务 | 416,667–666,667 |
| 小计 | 716,267–1,066,267 |
| 加20%项目储备后的总额 | 859,520–1,279,520 |

因此同一稳态下，6/12/24个月的现金情境分别约5.16–7.68、10.31–15.35、20.63–30.71百万美元。它们是**在假设成立时的费用乘法，不是CFSG所需时长的预测**。复用广度、专家工作量、重型证书或模型费4倍变化都可能使总额偏离；价格及购买地不同也会变化。

真实计划采用爬坡积分：`C_total = ∫(C_model(S(t),u(t)) + C_infra(t) + C_human(t))dt + 一次性获取/迁移/专用开发 + 预备金`。先导64槽、8–12人不该按256槽20人连续计费；后期关停闲置编队也应降低账单。每次扩容提案要同时报告边际集成产能、关键路径缩短和边际费用，而不只报告并发数。

## 13. 运转例子：一条跨队卡如何闭合

假设Lie识别队已经得到标准模型同构，但固定目标载体使用Steinberg固定点之导群中心商。识别队发消费者需求单，明确需要保持Steinberg映射的ambient同构及所诱导的商同构；不能只申请“证明两个群一样”。

复用员先在取得并审计的公开模块中检索一般固定点运输。若已有完整证明，接口员核对具体定义和宇宙，建立适配卡；没有则数学规划员拆为固定点、导群、中心、商四层。三个实施员并行处理可独立的层和生成性前提，明确后两层的实际依赖；基础队提供需要的子群/商同构API。

候选通过局部编译后，共享审计代理检查所用同构是否确实交错Steinberg映射、`FixedPointCandidate`的括号是否正确，消费者实际构造 `CFSGIndex` 并复合出口同构。遇到小参数被列表剔除，自动转交正规化卡，而不是放宽 `Valid`。只有消费者集成和独立检查通过才计一张闭合卡；四个子卡不让父出口提前完成。

相同协议用于M11呈示：生成关系验证和满射卡通过，不能关闭反向同构卡。Monster若还缺中心核分析，父包保持开放；调度器可继续其他25群和归纳/局部基础，另外安排结构证明研究及专家支持。系统以清晰未完成义务维持进度，不以模糊“模型已经识别”代替证明。

## 14. 本轮设计状态与下一步建设顺序

本文件只提交未来运行模型。没有声称启动256槽、取得完整公开CFSG实现、读过论文正文、编译Lean或测得上述成本/产能。建议实施顺序是：人类提供完整源码、工具链、文献和算力权限；代理建立证据/任务服务及两处重建；64槽完成消费者和深样本试验；依据测量扩到256；持续以完整依赖、例外和载体同构关闭全任务；最终独立发布。

四个最先建设的软件工件是：带版本和租约的定理卡账本、声明/来源/公理依赖索引、隔离工作树与内容寻址构建服务、可重放交接及消费者验收系统。没有这些公共机制，大量代理只会增加无法归责的尝试；建成并实测后，未来并发规模即可由有效吞吐和关键路径需求决定。
