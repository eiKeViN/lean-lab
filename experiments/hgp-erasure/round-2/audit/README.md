# Rechecking the 36M pair

The six main grade directories correspond to two rooms and three checkpoint crossings. Each grade.json records math-module source hashes, local imports, exact dependency closure identities, clean compilation outcomes, downstream declaration types, and the transitive axiom names returned by Lean.collectAxioms. Successful modules in a batch were imported together from supervisor-built oleans. Individual source paths for the final submissions are in ../submissions/manifest.json. A file under the SHEAF staging tree was evaluated separately from its status in the delivered project. Diagnostic scripts and files outside the math module set are retained in the evidence archive.

The trajectory-larch directories check distinct earlier source versions of the erasure, inference, and quotient modules. A successful full file may cease to build as its author extends it. A checkpoint crossing is a live copy, with timing and exact observed usage in ../metrics.json. The last strict-below snapshot is also identified there. Identical source with identical transitive local imports can reuse the same fresh result.

The two prefix directories are additional retrospective checks. In the free run the assessor kept lines 1–208 of Examples.lean and 1–273 of Strip.lean and closed their open scopes. In the SHEAF run the assessor kept lines 1–125 of Support.lean and closed its namespace. For Targets/Parameters.lean the assessor omitted two failing helper declarations (lines 70–84) and kept every other source byte. Each extracted input is supplied, along with the test of its imports and allowed axioms. These extractions do not change the original submissions or their grade for a whole file. Dependent SHEAF rank and inference drafts were also attempted against the recovered support prefix.

To reproduce a module batch, restore a snapshot into a new directory using the evidence archive. Use the pinned dependencies in the parent experiment. Set HGP_RUNTIME_ROOT to the absolute directory containing runtime and qecert. Give verify.py a source root, a JSON module-to-relative-source-path mapping, and a new output directory. For a normal grade.json this mapping is obtained from each entry's origin field. For a saved code archive, translate staging paths using the manifest. For a prefix test, assemble its extracted files alongside the unchanged dependency files using the origin paths in that batch. The batch uses a supervisor-owned cache in the parent of the output directory. Start a fresh cache when changing toolchains or dependency revisions.

The verify.py checker builds each module with lake env lean -o, instantiates the Audit.template.lean import and module list, and uses the original project toolchain and dependency manifest. No participant configuration, build output, binary, or generated olean is used as evidence. The separate whole-project checks used the two submitted Lake configurations after checking dependency pins. The allowed transitive axioms were propext, Classical.choice, and Quot.sound.
