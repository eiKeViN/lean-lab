# SHEAF 与自由 agent 的 HGP 擦除形式化实验

2026-11-11 · 单题配对案例研究 · 2 次 SHEAF，2 次自由运行 · GPT-6.1 Sol / high

## 结果要回答的问题

在相同模型、数学材料、离线库、推理用量和四个并发会话的条件下，预装 SHEAF 是否更容易交付大型 Lean 形式化？主指标是同一项目的五项数学要求全部通过独立验收。SHEAF 和自由组各为 **0/2**。复核发现两组均有可由 Lean 检查的局部成果。没有一个运行证明两条普遍适用的 HGP 条带公式，也没有一个运行交付完整工程。

原候选“证明 HGP 参数”已有精确匹配的上游定理，两组都得到了冻结的 QECert 和这一定理的出处。实际题面保留参数作为 A，在此之上考察 B 任意擦除区域支撑的逻辑空间秩公式、C 同 syndrome 的错误歧义与码距、D 任意变量条带的两条通式、E 两个端到端实例。两个实例是 [[5,1,2]] 和 [[8,2,2]]。独立有限检验覆盖 961 对小矩阵和 86,617 个擦除区域。一般性定理另由 Lean 和数学语义审查。

## 在什么预算下得到这个结果

每次运行至多 60 分钟，父子会话合计至多 1,200 万加权 token 单位。一个缓存输入 token 计 1，未缓存输入计 8，输出计 16，推理 token 已包含在输出中。这个换算是实验预登记的推理用量尺度。服务按推理步骤上报用量，因此停止点有小幅超额，未上报的在途生成无法精确计量。两组都开放同样的独立会话、消息、shell、持续工作目录和快照。所有参赛根会话和子会话均显式指定同一模型，关闭模型回退。四个运行各获得两个独占 CPU 编号，共用主机内存与文件缓存。

两个自由组都自发启用了全部四个会话。maple 先把通用秩公式、条带公式、HGP 参数及例子分别交给三名同伴；slate 把 B/C 放在一起，把 D、E 分别交出去，根会话自己处理 A。两组的三个子任务都在启动后 35 秒左右发出。这说明短提示足以在本题诱发拆分和并行。各模块最后能否接在一起，要看独立构建和下游调用。

## 核查源码时看到了什么

五项要求按完整数学陈述给分。A 要同时覆盖实际校验、长度、两个逻辑商空间的维数和两种代表元的距离下界；B 同时要求两条限制矩阵秩公式与互补关系；C 要等价判据和最小失败区域；D 要两条一般条带公式；E 要两个实例的全部参数和区域调用。下表将原项目中能单独导入的文件与截取原文前缀才通过的结果分开。前缀复核只补上关闭命名空间所需的 `end`，并附加检查命令，不改证明。

| 运行 | 原文件或工作稿的独立复核 | 未通过的位置 |
|---|---|---|
| SHEAF · cedar | 工作稿 A 的前 104 行能独立导入，11 项声明仅用允许公理。覆盖实际校验分块、正交性、长度、两种逻辑商空间的识别以及 Z 逻辑维数。 | 完整工作稿的 X 维数证明把一个 `LinearCode` 值传给了要求类型的 `Module.finrank`。后面的两个距离包装声明虽能局部通过公理查询，整份文件无法导入。B–E 只到计划阶段。 |
| SHEAF · flint | 复核了工作稿中的 11 个定义。它们确实指向 QECert 的 HGP 校验、复形、两个逻辑商和输入核。 | 新文件没有新的数学定理。没有覆盖任何一项完整目标。 |
| 自由 · maple | 参数文件的严格前缀验证了两种校验、正交性、长度、输入核对应及 Z 维数。擦除文件的前 132 行有 15 项声明通过，包括支撑子空间和逻辑商的接口。 | 原版擦除模块有证明脚本错误，依赖它的 C 无法直接导入。复核 C 时，“两种支撑维数为零当且仅当错误等价类唯一”这一单条证明的公理检查通过，但完整模块在逻辑引理与宇宙层级上报错。D 缺两条最终公式，E 的经典重复码距离证明未通过。 |
| 自由 · slate | `Erasure.lean` 整个原文件可重新构建，并从下游审计了 10 项声明。得到一个尚未完成 B 就有独立用途的结果：区域所支撑的逻辑维数，加上区域内边界的维数，等于区域内所有循环的维数。 | 参数文件前 45 行另外验证了校验矩阵、正交性、长度与 Z 维数。B 还缺把两个子空间维数再换成列限制矩阵秩的证明；D 的张量文件编译失败，E 没有两个例子的具体区域结论。 |

对 slate 的 B，可以用公式精确说明已走到哪一步。设循环空间为 \(Z\)，边界为 \(B\subseteq Z\)，区域坐标子空间为 \(V_E\)。它证明了

\[
\dim L(E)+\dim(B\cap V_E)=\dim(Z\cap V_E).
\]

要完成 B，还须分别把右边和左边第二项表达为经典校验矩阵的秩，再得到 X/Z 的互补关系。这个差距可以从公开声明和独立 Lean 输出直接检查。

## 解释范围与实验记录

- **第一次启动。** 四个会话已读到题面，却都收到控制器发出的只读权限声明，随即退出；当时没有写入尝试。修正会话的工作区权限声明后，新开四个干净会话，沿用相同题面、工具、组别和预算。这里的数学成绩取自这四次重跑；第一次启动的原因、四份返回和用量另行保留。
- **编译条件。** 两组共享的执行接口把单次 shell 调用限制为 120 秒。即使 agent 在命令内部指定更长上限，外层仍会终止调用，SHEAF 的常驻构建命令也受此影响。四次运行分别记录到 3、2、11、9 次外层超时。SHEAF 的脚本另外遇到缺少 `awk`、`rsync` 的问题。它们实际适配了部分工具；编译延迟本身的原因不能由这些缺失单独推出。监督端串行复核时，先前超时的部分源文件可以顺利完成，另一些给出了具体的 Lean 类型错误。
- **框架与并发。** 运行从固定版本的原版 SHEAF 指令和模板启动，角色会话改走共用的宿主接口，取代交互式 tmux。四席同时容纳启动者、维护者和组长后，只剩一个专职数学 worker。这轮能评估的是这一部署与预算；它没有测到 SHEAF 在更多 worker、多服务器或长时间运行中的收益。
- **语义与信任。** 五项任务允许等价的 Lean 表示。独立复核使用匿名化代码包、可信依赖和新工作目录，检查声明的数学含义、构建与传递公理。部分命名空间仍可能提示组别。参与者源码中的目标失败、复核器超时以及前缀通过各自单列。两组也都能调用实际的 comparator；它的内层 Landlock 在本机不可用，本轮共同验收依赖外层隔离、可信源重建和声明审查。
